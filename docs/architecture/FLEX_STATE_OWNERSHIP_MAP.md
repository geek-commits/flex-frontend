## Single-owner rule — conformance at current head

* **Correct:** `workspaceState` singleton → `useWorkspaceState` subscribe → many consumers (CallManager + Island + Assist). `TenantContextProvider` single context. `CapabilityProvider` single navigation + guard model. `DashboardProvider` single polling owner. `ExternalWorkspaceHost` single host for both CRM (`/agent`) and Social (`/agent/social`) — native `socialRepository`/`useSocialWorkspace` removed, Customer 360 uses minimal `customer-360-social-mock.ts` only for POC timeline linking to `/agent/social`.
* **Anti-pattern to avoid:** route store + context + local copy + Island copy of the same call truth; separate UI-owned `Assist` owner when idle; separate UI-owned conference participant truth; reintroducing native Social realtime owner alongside external Social (external owns realtime per ADR-003 update).

## Forward refactors (deferred to Increment 3+)

* Tenant switching must re-scope/invalidate: `queries`, realtime subscriptions (once WS exists), cached data, route selections, permission scopes — **ADR-002** owns this contract.
* Permission evaluation boundary stays `has(capability)` first, backend authority later — **ADR-005**.
* No mega-store: prefer domain boundaries `telephony/`, `assist/`, `social/`, `tenant/`, `auth/`, `monitoring/`, `reports/` — compatible with current `features/*` + `domain/*` layout (§26).

## Gaps recorded (not fixed in Increment 1)

* Tenant context is authoritative but non-scoping — see `FLEX_HARDENING_BASELINE.md` §4 and ADR-002.
* Permission model is UI-only — `auth/capabilities.tsx:8-13` deferred; backend authority NOT VERIFIED.
* Realtime is polling-only — staleness is UI-only without reconnect semantics — see `FLEX_REALTIME_CHANNEL_AUDIT.md`.
